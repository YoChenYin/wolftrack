Decision Lab
Professional Market Decision System

不預測市場，訓練決策。放在總經頁最上方——使用者用10分鐘走完一次基金經理人的盤前流程，得到一份誠實的 Today's Trading Report，自己做決定。

放置位置｜總經頁最上方 使用者｜24–45歲，有交易經驗 每日投入｜10分鐘 不喊單、不預測

00

摘要與定位

Decision Lab 是總經頁的新首屏——在既有「台股歷年月份表現」季節性面板之上，新增一層「今天」視角的全球市場決策儀表板。兩者互補：季節性面板回答「歷史上這個月通常如何」，Decision Lab 回答「今天這個當下，值不值得交易」。

這也跟本專案已經上線的台指期 Decision OS（/futures 頁，見 docs/taifex-decision-os-prd.html）形成分工：台指期 Decision OS 是「台股期貨執行層」，八層框架裡的 L1(全球市場)／L2(總體風險) 兩層當時因為資料源缺口沒有分數；Decision Lab 的 Module 1(Global Market) 與 Module 2(Macro) 一旦上線，就是那兩層缺的資料源——這不是兩個獨立產品，是同一套決策骨幹的兩個層級，工程上應該讓台指期 Decision OS 未來直接讀 Decision Lab 的每日快照當輸入，而不是重算一次。

誠實的規模提醒：使用者提供的規格涵蓋 16 個模組，其中 Module 13–16（Decision Replay／Portfolio Manager／Personal Growth／Decision Journal）需要「使用者真實下的單」這個資料——目前系統完全沒有交易紀錄輸入機制。這四個模組看起來是「進階功能」，實際上需要先建一個全新的基礎功能：交易日誌輸入（Trade Log），否則 Decision Quality Score／Trading Maturity Score 都無米可炊。這點在第16節開發 Roadmap 會排進正確的順序，不會假裝這是「之後才加的小功能」。

01

產品原則

  1. 建立流程，而非預測市場。每一個模組輸出的是「證據」，不是「訊號」——最終畫面永遠是給使用者資訊去自己判斷，不是一個「買/賣」按鈕。
  2. 提升決策品質，而非追求短期績效。Decision Replay（M13）刻意不評估「今天賺不賠」，評估「今天的流程有沒有做對」——賠錢但流程正確，分數仍然高。
  3. 像基金經理人一樣思考。Fund Manager Notes（M14）、AI Coach（M13）都刻意用機構投資人語氣，不是散戶社群語氣。
  4. 把每天的分析變成可累積的知識資產。M16 Decision Journal 讓每天的 Decision Lab 快照都變成未來可搜尋、可回顧的紀錄，而不是看完就消失的即時資訊。

02

User Flow

盤前（開盤前，使用者的10分鐘）
  總經頁 → Decision Lab 區塊置頂
    → 看 Trading Score + Market Regime（30秒懂今天狀態）
    → 依序掃過 M1–M6（Global→Macro→Volatility→Liquidity→Breadth→Sentiment）
    → 看 M9 Scenario Generator（今天三種劇本）
    → 看 M10 Trading Plan + M11 Risk Management（今天適合什麼打法、部位多大）
    → 若真的要下單：M12 Execution Checklist 全部打勾才顯示 Ready To Trade
    → （可選）問 AI Copilot 任何一個模組的細節

盤中
    → （v1不做）即時更新非必要，維持「盤前一次性完成分析」的定位

盤後（收盤後，automated）
    → M13 Decision Replay 自動產生：Actual Market Story + Scenario Accuracy
    → 若使用者有登記今天的交易（Trade Log）→ 額外算 Decision Quality Score
    → M16 Decision Journal 自動寫一篇日誌，使用者可以事後補充/搜尋

週期性
    → 每週一自動產生 Weekly Report（M13）
    → 每月自動產生 Monthly Report（M13）
    → M15 Trading Maturity Score 隨 Trade Log 累積量增加而逐漸有意義

路徑內容

十六個模組

每個模組標示可行性：已驗證＝本專案已有可用資料源／已上線；推測可行＝已知同類資料源存在但本session未實測；缺口＝需要新資料源調研或付費方案，甚至是全新子系統（如 Trade Log）。

M1

Global Market

全球市場 ◐ 部分可行

顯示 SPX / NASDAQ / SOX / Dow / Russell 2000 / DAX / Nikkei / Hang Seng / Bitcoin / Gold / Oil / DXY / US10Y / US2Y，紅綠配色、日漲跌、開盤跳空(Gap)、趨勢箭頭，用 Heatmap 排列。

SPX (S&P 500)FRED SP500已驗證，本專案已上線（總經頁既有季節性面板同一個序列）
DXYFRED DTWEXBGS已驗證（台指期Decision OS已用）
US10Y／US2YFRED DGS10／DGS2已驗證

M2

Macro

總體事件 ✕ 缺口

今日／未來重大事件：CPI、PPI、FOMC、Fed Speech、GDP、PMI、NFP，含重要程度、倒數時間、影響程度。命中時系統提醒「Avoid aggressive trading」——這一項邏輯已經在台指期 Decision OS 的 Gate #1–#8 設計過，可以直接共用同一張事件行事曆表（MacroEvent，見台指期PRD第11節），不用重新設計，只是那張表目前也是空的，需要資料維護流程或找到可靠的財經行事曆 API。

M3

Volatility

波動度 ◐ 部分可行

VIX、VVIX、MOVE、Skew、Put/Call Ratio，並附白話解讀（例如「VIX↑ 但 SPX↑ = 高波動多頭市場」）。

指標資料源狀態
VIXFRED VIXCLS已驗證（台指期Decision OS PRD已列為L1輸入）
美股整體 Put/Call RatioCBOE總量Put/Call，非本專案已有的TAIFEX PCR（那是台指選擇權專用）缺口，需另找CBOE資料源
VVIX、MOVE、SkewCBOE系列指數，通常需付費或另尋免費鏡射源缺口
M4

Liquidity

流動性 ◐ 部分可行

ETF Flow、外資期貨部位、未平倉量(OI)、融資、融資賣出、Dollar、Bond Yield，逐項給 Bullish／Neutral／Bearish 判斷。

台指期部分（外資期貨部位／OI）已經在台指期 Decision OS 有雛形（tw_futures_daily已上線，三大法人期貨未平倉端點已確認但未接入每日累積）；ETF Flow（美股）與台股融資融券則是缺口，需另外調研資料源。

M5

Market Breadth

市場廣度 ✕ 缺口

Advance/Decline、New High/New Low、類股輪動、SPX等權重 vs 市值加權、大型股貢獻度——需要美股全市場逐檔資料，本專案目前的資料源（TWSE/TAIFEX/FRED/FinMind）都不涵蓋美股個股層級，這是全新的資料源需求。

M6

Sentiment

市場情緒 ✕ 缺口

Fear & Greed、AAII、Positioning、Gamma Exposure、Dealer Position，翻譯成白話（例如「市場開始過度樂觀」）。Gamma Exposure／Dealer Position 是 SqueezeMetrics／SpotGamma 這類專業付費資料商的產品，AAII 每週有公開問卷但需要另外整理，CNN Fear&Greed 沒有官方開放API。全部列為缺口，v1 不建議承諾。

M7

Market Regime Engine

市場狀態引擎 ● 純運算，可行

這是核心模組，但屬於運算邏輯設計，不依賴新資料源——用 M1(趨勢)＋M3(波動度)＋M5(廣度) 三組讀值分類，即使 M5 暫缺，先用 M1+M3+既有的台股技術面（沿用台指期Decision OS的L6技術分析）也能先跑一個簡化版。

Regime定義
Strong Bull價格站上所有均線且持續創高，ADX>25，VIX偏低且穩定
Weak Bull價格緩漲，均線糾結或部分翻多，ADX<25
Range價格在區間內反覆，布林帶寬收窄，ADX<20
Weak Bear價格緩跌，尚未破底加速
Strong Bear價格加速破底，VIX明顯上升
VolatileATR/波動度急速擴張，方向不明
Distribution價格高檔震盪但廣度轉弱（大型股撐盤、多數個股走弱）
Accumulation價格低檔震盪但廣度開始改善
CapitulationVIX急升＋單日跌幅劇烈＋成交量爆量，通常是短期底部特徵而非賣出訊號
M8

Trading Score

交易評分 ● 純運算，可行

沿用台指期 Decision OS 已經驗證過的「加權層分數」設計模式，這裡的權重依使用者需求給定：

因子權重
Macro20%
Liquidity20%
Trend20%
Sentiment15%
Volatility15%
Breadth10%

⚠️ 這組權重是使用者給的初始假設，跟台指期 Decision OS 一樣需要回測校準；且 Liquidity/Sentiment/Breadth 三個因子目前資料源缺口最大（見上方M4-M6），v1上線時這三項會用「資料不足時中性化處理」（缺資料的因子貢獻分數記為0，不是假裝有資料硬湊），並在UI上誠實標示「此因子資料不足」。

M9

Scenario Generator

情境生成器 ● 規則式可行，敘事可加LLM

每天產生 Scenario A/B/C（例如「開高走高續漲」65%、「橫盤」25%、「賣壓」10%），各自附條件／風險／策略。v1 用規則式機率（依 Regime＋Trading Score 分佈映射到三個劇本），敘事文字可以疊加 Claude API 生成更口語化的描述——但機率本身必須是規則算出來的，不能讓LLM自己編機率（那樣無法回測校準、也違反「不是預測市場」的產品原則）。

M10

Trading Plan

交易計畫 ● 純運算，可行

依 Regime 判斷今天適合 Trend Following／Breakout／Mean Reversion／Scalping／No Trade，附理由。對應規則：Strong Bull/Bear→Trend Following；Range→Mean Reversion；Volatile→No Trade 或大幅降低頻率；Accumulation/Distribution→觀察為主。

M11

Risk Management

風險管理 ● 已有雛形

今日最大建議部位（100/75/50/25%）、最大虧損限額、停損提醒、事件提醒——直接沿用並延伸台指期 Decision OS 已上線的 riskEngine.ts／UserRiskProfile，不重寫一套新的。

M12

Execution Checklist

執行檢查表 ● 純UI，可行

Trend確認／Volume確認／VWAP／Higher Timeframe／Entry／Stop Loss／Position Size／Risk Reward 八項勾選，全部完成才顯示「Ready To Trade」。這是最簡單的模組——單純的使用者互動狀態，不需要新資料源，v1第一批就能做。

AI

Decision Copilot

右側常駐助手 ● 需要LLM整合，設計上可行

系統 Prompt 必須明確約束「只能教育、不能給明牌」——技術上用一個固定的 system prompt 前綴 + 把當下頁面看得到的 Decision Lab 資料（Trading Score/Regime/當前模組明細）當 context 灌進去，讓 Copilot 只針對「已經顯示在畫面上的資料」做解釋，不去外部生成新的市場預測。

M13

Decision Replay

決策回放 ◐ 部分可行，Decision Quality需要Trade Log

可以做（不需要使用者輸入）

  • Morning Snapshot：回顧當天M8 Trading Score／M7 Regime／M11 Risk Level／M9三劇本的存檔——純粹讀 daily_snapshots 歷史列。
  • Actual Market Story：收盤後用當日OHLC分類「開高走高／開高走低／震盪／突破／假突破／V轉／Gap Fill／Trend Day／Range Day」，規則式判斷＋LLM包裝成一段像基金經理人盤後報告的敘事。
  • Scenario Accuracy：拿 Actual Market Story 的分類結果去對當初M9的三個劇本，判定 Correct／Incorrect／Not Triggered，並長期累積每種劇本的命中率統計。

做不到（需要先有 Trade Log）

Decision Quality Score（是否忽略重大事件／逆勢交易／違反風控／低分時仍交易／符合自己的計畫）本質上是在評估「使用者實際做了什麼」，系統目前完全沒有交易紀錄輸入。這不是「AI Coach還沒接上」的問題，是資料完全不存在的問題。M13 的 Decision Quality／AI Coach 兩塊必須排在「先做 Trade Log 輸入功能」之後，見第16節Roadmap。

Weekly／Monthly Report 是既有每日快照的週期性彙總，屬於純運算，v1可以只做「市場面」的週報/月報（Trading Score走勢、Regime分布、Scenario命中率），Decision Quality相關統計等Trade Log上線後再補。

M14

Portfolio Manager Mode

基金經理人視角 ● 純運算＋LLM敘事，可行

Risk Budget／Position Size Recommendation／Exposure Recommendation／Confidence Level／Capital Allocation／Portfolio Heat 全部是 M7(Regime)＋M8(Trading Score)＋M11(Risk Engine) 的重新包裝與呈現，不需要新資料源，是視角轉換而不是新資料。Fund Manager Notes（100–200字晨間筆記）用 LLM 生成，輸入是當天M1-M11的完整快照，輸出限制字數與語氣（機構投資人晨會筆記，不是散戶社群語氣）。

M15

Personal Growth Dashboard

個人成長儀表板 ✕ 需要 Trade Log

Decision Quality／Execution Discipline／Patience Score／FOMO Score／Rule Compliance／Risk Discipline／Scenario Accuracy／Holding Quality／Consistency 彙總成 Trading Maturity Score——全部依賴使用者的實際交易行為資料，跟M13的Decision Quality是同一個根本問題：沒有Trade Log就沒有這個模組。

M16

Decision Journal

決策日誌 ◐ 市場面可行，決策面需Trade Log

每天自動生成日誌（市場摘要／最大風險／最大機會／AI總結）可以直接用 M13 的 Actual Market Story 產出，v1就能做且可全文搜尋；「今天最大的錯誤／今天最好的決策」這類需要對照使用者實際行為的欄位，一樣要等 Trade Log。

04

Design System

融合 Bloomberg Terminal 的資料密度、TradingView 的圖表可信度、Apple 的留白節奏、Linear 的介面速度感、Notion 的資訊架構彈性。極簡、黑色系為主、專業金融感，Glassmorphism 只用在懸浮層（tooltip／Copilot側欄），不用在卡片本體（卡片維持實色背景，避免資料被模糊背景干擾閱讀，這是Bloomberg優先於玻璃感的地方）。

Token用途色值（深色）

07

Database Schema

與台指期 Decision OS 相同慣例（snake_case資料表）。刻意把 M1-M12（市場面，可以現在做）跟 M13/M15 需要的 TradeLog（決策面，是先決條件）分開標示。

/// M1-M6 每日快照：全球市場/總體事件/波動度/流動性/廣度/情緒，一天一筆，欄位依可行性逐步填入
/// （資料源缺口的欄位先留null，見PRD第14節，不假裝有資料）
model MacroDailySnapshot {
  id            BigInt   @id @default(autoincrement())
  snapshotDate  DateTime @unique @map("snapshot_date") @db.Date

  globalMarketData   Json     // M1: {ticker: {close, changePct, gapPct}}[]
  macroEvents        Json?    // M2: 當天/未來事件清單快照
  volatilityData     Json?    // M3
  liquidityData      Json?    // M4
  breadthData        Json?    // M5（v1通常是null，資料源缺口）
  sentimentData      Json?    // M6（v1通常是null，資料源缺口）

  regime             MarketRegime
  tradingScore       Int      @map("trading_score")
  scoreBreakdown     Json     @map("score_breakdown") // 各因子貢獻分數，缺資料因子記0並標註

  fundManagerNote    String   @map("fund_manager_note") @db.Text  // LLM生成，100-200字

  createdAt DateTime @default(now()) @map("created_at")
  @@map("macro_daily_snapshots")
}

enum MarketRegime {
  strongBull weakBull range weakBear strongBear
  volatile distribution accumulation capitulation
}

/// M9 情境生成器：每天三個劇本＋收盤後回填實際結果
model ScenarioForecast {
  id            BigInt   @id @default(autoincrement())
  snapshotDate  DateTime @map("snapshot_date") @db.Date
  label         String   // "A" | "B" | "C"
  description   String   @db.Text
  probability   Int
  condition     String   @db.Text
  risk          String   @db.Text
  strategy      String   @db.Text

  actualOutcome ScenarioOutcome? @map("actual_outcome")  // 收盤後M13填入

  @@unique([snapshotDate, label])
  @@map("scenario_forecasts")
}
enum ScenarioOutcome { correct incorrect notTriggered }

/// M13 收盤後決策回放：市場面部分（不需要Trade Log）
model DecisionReplay {
  id                 BigInt   @id @default(autoincrement())
  tradeDate          DateTime @unique @map("trade_date") @db.Date
  actualMarketStory  String   @map("actual_market_story") @db.Text
  marketPattern      String   @map("market_pattern") // "開高走高" | "假突破" | "TrendDay" ...
  decisionQualityScore Int?   @map("decision_quality_score") // null，直到有 TradeLog 才能算
  aiCoachNote        String?  @map("ai_coach_note") @db.Text  // 同樣依賴TradeLog才有意義的內容

  @@map("decision_replays")
}

/// ⚠️新的基礎功能，M13的Decision Quality／M15整個模組的前提，不存在就無法評估「使用者做了什麼」
model TradeLog {
  id           BigInt   @id @default(autoincrement())
  entryDate    DateTime @map("entry_date")
  instrument   String   // "MTX" | "TX" | 個股ticker
  direction    String   // "long" | "short"
  entryPrice   Decimal  @map("entry_price") @db.Decimal(12, 2)
  exitPrice    Decimal? @map("exit_price") @db.Decimal(12, 2)
  positionSize Int      @map("position_size")
  stopLoss     Decimal? @map("stop_loss") @db.Decimal(12, 2)
  takeProfit   Decimal? @map("take_profit") @db.Decimal(12, 2)
  followedPlan Boolean? @map("followed_plan") // 使用者自評是否照計畫執行
  linkedSnapshotDate DateTime? @map("linked_snapshot_date") @db.Date // 關聯當天的MacroDailySnapshot

  createdAt DateTime @default(now()) @map("created_at")
  @@map("trade_logs")
}

/// M15 Trading Maturity Score：週期性從 TradeLog + DecisionReplay 彙總算出，不是每天算
model TradingMaturitySnapshot {
  id              Int      @id @default(autoincrement())
  periodStart     DateTime @map("period_start") @db.Date
  periodEnd       DateTime @map("period_end") @db.Date
  maturityScore   Int      @map("maturity_score")
  subScores       Json     // {disciplineScore, patienceScore, fomoScore, ruleComplianceScore, ...}

  @@map("trading_maturity_snapshots")
}

/// M16 每日自動日誌，可全文搜尋
model DecisionJournalEntry {
  id           BigInt   @id @default(autoincrement())
  entryDate    DateTime @unique @map("entry_date") @db.Date
  marketSummary String  @map("market_summary") @db.Text
  biggestRisk   String  @map("biggest_risk") @db.Text
  biggestOpportunity String @map("biggest_opportunity") @db.Text
  aiSummary     String  @map("ai_summary") @db.Text
  // 下面兩個欄位需要TradeLog才會有內容，v1可為null
  biggestMistake String? @map("biggest_mistake") @db.Text
  bestDecision   String? @map("best_decision") @db.Text

  @@map("decision_journal_entries")
}

開發 Roadmap

Phase 1 — 市場面 MVP（資料源已驗證/推測可行的部分）

  • M1（SPX/DXY/US10Y/US2Y先上，其餘逐步補）、M7 Regime Engine、M8 Trading Score（缺資料因子記0並標示）、M9 Scenario（規則式機率）、M10 Trading Plan、M11 Risk Management（重用台指期Decision OS的risk engine）、M12 Execution Checklist。
  • 置頂於總經頁，跟既有季節性面板共存。

Phase 2 — 決策回放（市場面）與 AI 整合

  • M13 Decision Replay 的市場面部分（Morning Snapshot/Actual Market/Scenario Accuracy）。
  • Decision Copilot（Claude API整合）、M14 Fund Manager Notes（LLM敘事）。
  • M16 Decision Journal 市場面部分，全文搜尋。

Phase 3 — Trade Log 基礎建設

  • 這是解鎖 M13完整版/M15 的關鍵前提，必須獨立排一個階段，不能當作「順便做」。
  • 建 TradeLog 輸入介面（/macro/trades），使用者自己登記進出場、部位、是否照計畫執行。
  • Decision Quality Score、AI Coach、M15 Trading Maturity Score 都在這個階段之後才能真正上線，而不是流於「顯示假資料的空殼模組」。

Phase 4 — 資料源擴充

  • 調研 SOX/Russell/DAX/Nikkei/HangSeng、CBOE Put/Call、美股Breadth、台股融資融券、事件行事曆等缺口資料源，逐步把 M2/M3/M4/M5/M6 的「資料不足」因子填滿。
  • 回測校準 M8 Trading Score 的因子權重（目前是⚠️假設值）。

Decision Lab — Product & Engineering Spec v0.1。與 docs/taifex-decision-os-prd.html（台指期 Decision OS）共用同一套決策骨幹設計原則，二者是總經層與台股期貨執行層的關係，非各自獨立的產品。所有標註 ⚠️ 的數值為初始假設，需以歷史資料回測校準。
