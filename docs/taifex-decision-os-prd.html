Decision OS

不是報明牌網站，是一套讓新手每天用20分鐘，走完基金經理人的分析流程，得到一句誠實結論——包括「今天空手」——的決策系統。

00

設計哲學

這套系統的 KPI 不是「每天都有訊號」，而是減少使用者做出的錯誤交易次數。一個新手交易者最大的敵人不是看錯方向，而是在沒有優勢（edge）的日子裡，因為「不甘心今天沒交易」而硬凑一筆單。

因此整個系統只有一個不能妥協的原則：當市場沒有給出足夠清晰的優勢時，系統要有勇氣說「今天空手」，而且要把這句話說得和「建議做多」一樣有自信、一樣有理由支撐——不是含糊的「資料不足」，而是「我看過八層分析，結論是今天不值得冒險，理由如下」。

其次，系統要像基金經理人一樣思考，不能像明牌网站一样喊單。基金經理人不會直接說「買」，他會先看國際盤、再看總體風險、再看資金流向、最後才談技術面與進場價位——如果任何一關卡关過不了，後面都不用看了。這套 OS 的八層架構、以及每一層都能「否決」下一層的設計，就是在把這個思考順序系統化。

01

使用者輪廓與產品原則

主要使用者
25–40 歲、有正職工作的上班族／小資族，希望建立長期穩定的交易系統，而非追求刺激或高頻交易。
每日時間預算
20–30 分鐘，通常在通勤、午休、下班後的零碎時間查看——介面必須讓「今天要不要交易」在 30 秒內有答案，細節分析可展開但不強迫閱讀。
交易商品
微型台指期貨（MTX），波段操作，持有 2–15 天，明確排除當沖——所有指標與 Gate 的時間顆粒度都以「日」為單位，不處理盤中逐筆訊號。
產品不是
不是報明牌網站、不是訊號推播機器人、不是自動下單系統（v1 沒有下單 API 整合，只做決策輔助）。

核心產品原則：永遠先展示結論與信心分數，再展示推理過程；永遠展示「反對這個結論的理由」，不只展示「支持的理由」——這是本 OS 與一般技術分析網站最大的差異，也是「Decision Agent 辯論」設計（見第 6 節）存在的原因。

02

系統架構總覽

資料由下往上流動、決策由上往下否決。八層分析框架先各自產生分數與旗標，交給評分引擎彙總，再交給四個 Agent 進行質化辯論，關卡引擎與風控引擎全程並行檢查，任何一關不通過就直接截斷輸出。

// 每日 Pipeline 執行順序（並非單純由上到下——Gate 可以在任何一步後直接截斷）
1. 資料蒐集層     — 八層各自的資料源，每日排程抓取／快取
2. 評分引擎       — 18+ 項核心指標 → -2..+2 → 加權彙總成 8 層分數
3. Gate 引擎      — 35 項關卡並行檢查（與分數無關，任何一項 fail 就降級輸出）
4. Agent 辯論引擎 — Macro / Flow / Technical / Risk 四個 Agent 各自表態
                    → Decision Agent 綜合仲裁，產出最終建議 + 正反理由
5. 風控引擎       — 針對 Decision Agent 的建議計算實際部位、停損、停利、R值
6. 輸出層         — 今日市場 Dashboard（9 項標準輸出，見第 9 節）

八層分析框架與 Agent 的對應關係：Macro Agent 消化 L1（全球市場）+ L2（總體風險）；Flow Agent 消化 L4（法人籌碼）+ L5（市場情緒）；Technical Agent 消化 L3（台股環境）+ L6（技術分析）；Risk Agent 橫向消化 Gate 引擎與風控引擎的結果，並對其餘三個 Agent 的建議有否決權。L7、L8 不產生獨立訊號，是三個分析 Agent + Risk Agent 綜合後的「輸出層」。

03

八層分析框架

以下逐層說明目的、資料需求、判讀邏輯與對下一層的影響。每一層都標註「是否可單獨否決全局」——這是本 OS 與一般加權評分模型最大的不同：不是所有分數都平等，有些層級（尤其 L2）擁有否決權，不需要贏得多數票。

L1

全球市場

Global Markets
目的
判斷隔夜國際市場，尤其美股科技股與半導體股，留下的方向與情緒，作為台股開盤前的定錨。
為什麼重要
台股電子權重超過六成，那斯達克與費城半導體指數（SOX）走勢與台股次日開盤跳空方向高度相關；VIX 代表全球風險偏好；美元強弱與美債殖利率牽動外資對包含台灣在內的新興市場資金去留。這一層決定「今天要不要用比較嚴格的標準看多單」。
需要資料
NASDAQ 收盤與漲跌幅、SOX 收盤與漲跌幅、VIX 指數、美元指數（DXY）、美國 10 年期公債殖利率、美國 2 年期公債殖利率（用於利差／殖利率曲線）。
資料來源
VIX — FRED 序列 VIXCLS（免金鑰 CSV，本專案已驗證此匯出方式可行）。 美元指數 — FRED DTWEXBGS（貿易加權美元指數）。 10 年期殖利率 — FRED DGS10；2 年期 — FRED DGS2。 NASDAQ／SOX — 尚待補齊：Polygon.io 免費方案實測僅開放約 2 年歷史（本專案在建置 S&P 500 對照序列時已踩過這個限制），且不含 SOX 這類產業指數；需要另尋資料源或升級方案，見第 15 節資料源現況總表。
如何判讀
NASDAQ／SOX 用單日漲跌幅分級；VIX 用絕對水位＋方向分級（<15 平靜、15–20 正常、20–30 警戒、>30 恐慌）；殖利率曲線看 10Y–2Y 利差由負轉正、或倒掛程度是否惡化。

Bullish

NASDAQ／SOX 收紅且漲幅 > 0.5%，VIX < 18 且下降，美元指數走弱，殖利率曲線無惡化。

Neutral

NASDAQ／SOX 漲跌介於 −0.3%～+0.3%，VIX 持平於 18–22 區間，美元指數變化不顯著。

Bearish

NASDAQ／SOX 收黑且跌幅 > 1%，VIX > 25 且上升，美元急升，殖利率倒掛加深或急速變陡。

是否需等待
若 NASDAQ／SOX 與 VIX 訊號互相矛盾（例如那指上漲但 VIX 同步跳升），視為高不確定性，建議等待台股開盤價量確認後再判斷，本層不單獨產生決策。
對下一層影響
本層是 L2 總體風險判讀的背景；若本層強空，L6 技術分析要產生「做多」訊號時，需要更高強度才能通過（等於動態提高進場門檻，實作上反映在 Agent 辯論引擎的信心分數加權）。
L2

總體風險

Macro Risk Events
目的
辨識未來 1–3 個交易日內是否有高波動事件，避免波段倉位在資訊真空期後暴露於劇烈跳空風險中。
為什麼重要
FOMC 利率決議、CPI、非農就業（NFP）等總經數據公布，常造成台指期出現超過 1.5%–3% 的異常波動。波段倉位需要過夜曝險，在這類事件前開新倉，本質上是在承擔一個與「你的交易邏輯」無關的風險。
需要資料
FOMC 會議與利率決議日期、美國 CPI／PCE 公布日期、NFP 非農公布日期、台灣央行理監事會日期、台積電法說會日期、那斯達克七雄財報週期、國內外重大選舉或公投時程、台指期結算日（每月第三個週三）。
資料來源
美國經濟數據日曆——尚待補齊，FRED 本身不含未來事件日曆，需另尋外部行事曆資料源（例如財經行事曆 API），本專案尚未驗證任何一支；台積電法說會／台灣央行——可由公開新聞公告日期建立一張人工維護的「事件日曆」表，作為 v1 的務實解法；台指期結算日——可用規則計算（每月第三個週三），不需外部資料源。
如何判讀
檢查未來 48 小時內是否落在任一「高風險事件」名單內，以及事件距離現在的時數。本層不產生方向性分數，是本 OS 八層中唯一「只做旗標、不做評分」的層級——它的工作是否決，不是投票。

本層無 Bull／Bear／Neutral 三態，只有「風險窗口開啟」與「風險窗口關閉」兩種狀態。詳細規則列在 Gate 引擎（第 7 節）Gate #1–#8。

是否需等待
是——只要命中任一事件窗口，直接觸發 Gate 引擎「禁止新倉」，不論其餘七層評分多高，Decision Agent 都必須將這個否決權反映在最終建議中。
對下一層影響
若本層觸發風險旗標，L7 交易計畫直接輸出「今日空手，等待事件落地」，可以跳過後續技術面細節判讀，節省使用者的 20 分鐘。
L3

台股環境

TW Market Environment
目的
確認台股大盤本身（不含期貨）目前的價、量、廣度是否支持趨勢延續，把 L1 的國際線索收斂到台灣市場的實際反應。
為什麼重要
國際盤方向不會百分之百傳導——台股有自己的資金結構與族群輪動。如果國際盤偏多但台股當天上漲家數反而少（廣度不佳），代表這波多頭「不健康」，波段的持續性存疑。
需要資料
加權指數（TAIEX）日 K 線、漲跌家數比、成交金額、新台幣兌美元匯率、電子權值股（台積電等）對大盤的貢獻度。
資料來源
TAIEX 日線——TWSE 官方 API，已驗證可用，本專案已回填 20 年歷史；漲跌家數比——TWSE 每日市場成交資訊，待整合；新台幣匯率——央行或 FRED 皆有對應序列，待整合。
如何判讀
TAIEX 相對 20 日均線的位置與斜率；漲跌家數比是否與指數漲跌方向一致（背離＝廣度警訊）；台幣單日貶值超過 0.5% 視為外資流出的間接訊號。

Bullish

TAIEX 站上 20MA 且上揚，漲家數 > 跌家數 1.5 倍以上，台幣持平或升值。

Neutral

指數在 20MA 附近糾結，漲跌家數接近，台幣波動 < 0.3%。

Bearish

TAIEX 跌破 20MA 且下彎，跌家數明顯多於漲家數（廣度轉弱），台幣單日貶值 > 0.5%。

是否需等待
若指數上漲但廣度背離（漲家數反而減少），標記為「假突破疑慮」，建議等待隔日確認，不視為足夠的做多證據。
對下一層影響
本層結果是 L6 技術分析（個股層級的均線／動能指標）的大盤背景校正——同樣的均線多頭排列，在廣度健康 vs. 廣度背離的情境下，Technical Agent 給的信心分數會不同。
L4

法人籌碼

Institutional Flow
目的
追蹤外資、投信、自營商在台指期與現貨的部位變化，判斷「聰明錢」目前的傾向——這是台灣期貨市場散戶最重視、也最容易被誤讀的一層。
為什麼重要
外資台指期未平倉淨部位長期被視為台股期貨市場最重要的籌碼指標之一；融資餘額變化反映散戶追高殺低的情緒，是重要的反指標；選擇權未平倉量比（Put/Call Ratio）反映整體市場的避險需求強弱。
需要資料
三大法人台指期未平倉淨口數（外資／投信／自營）、融資餘額與使用率變化、台指選擇權 Put/Call 未平倉量比、外資現貨買賣超金額。
資料來源
選擇權 Put/Call 比——TAIFEX open API PutCallRatio，已驗證可用且已上線（本專案已建置 tw_options_put_call_ratio 資料表，每日排程累積）。 三大法人期貨未平倉——TAIFEX open API MarketDataOfMajorInstitutionalTradersDetailsOfFuturesContractsBytheDate，已驗證可用，但只回傳當日快照、無歷史範圍參數，需要每日排程逐日累積，尚未接進本 OS（第 15 節有完整落差說明）。 融資餘額——TWSE 官方每日信用交易統計，待整合，資料源需再確認。 外資現貨買賣超——本專案既有 tw_institutional_trading 資料表已涵蓋個股層級，大盤層級的加總邏輯待建置。
如何判讀
外資台指期淨部位由空翻多、或淨多顯著擴大＝偏多訊號；融資餘額連續增加且股價滯漲＝過熱警訊（反指標）；Put/Call 未平倉量比 > 120% 或 < 70% 視為情緒極端，此層的判讀邏輯詳見第 4 節評分引擎的個別指標定義，尤其 PCR 是反指標用法，需要特別留意方向不要判讀反了。

Bullish

外資期貨淨多顯著增加，融資餘額緩降（籌碼安定），PCR 落在中性偏樂觀但未達過熱。

Neutral

外資期貨淨部位持平，融資餘額變化平緩，PCR 貼近 100%。

Bearish

外資期貨淨空顯著擴大，融資餘額爆量增加但股價滯漲（散戶追高），PCR 過度樂觀（< 70%，反指標偏空）。

是否需等待
若外資期貨與外資現貨方向矛盾（例如現貨買超但期貨空單增加），這通常代表法人在做避險而非方向性表態，建議標記「訊號不純」，不單獨作為進場依據。
對下一層影響
本層是 Flow Agent 的主要輸入；當本層與 L6 技術面方向一致時，Decision Agent 對最終建議的信心分數會顯著提升——這是本 OS 判斷「今天是不是好日子」最重要的交叉驗證之一。
L5

市場情緒

Market Sentiment
目的
量化目前市場參與者的集體心理狀態是否處於極端（過度樂觀或過度悲觀），因為極端情緒往往是短期反轉的領先指標，而不是趨勢延續的理由。
為什麼重要
波段交易最怕在情緒高點追多、情緒低點殺低。這一層存在的目的就是防止 Technical Agent 單純看「趨勢很強」就無腦做多，忽略了「強到過熱」的風險。
需要資料
選擇權 Put/Call 量比與未平倉比（與 L4 共用資料源，但這裡用「情緒極端」的角度判讀，不是「籌碼方向」的角度）、大額交易人未沖銷部位集中度、新聞與社群情緒指數（可選）。
資料來源
大額交易人未沖銷部位——TAIFEX open API OpenInterestOfLargeTradersFutures，端點已找到，尚未實測回傳內容。 新聞／社群情緒——未有資料源，屬於 v2 以後的加分項，不建議列入 v1 MVP。
如何判讀
PCR 未平倉量比在本層視為「情緒溫度計」：> 120% 代表市場過度悲觀（避險需求極高），< 70% 代表市場過度樂觀（避險需求極低）——兩個極端都要提高警覺，而不是像 L4 那樣單純判讀方向。

Bullish

情緒指標從極度悲觀區間回升（PCR 從 > 120% 回落），代表恐慌可能已經釋放完畢，這是本層唯一產生「偏多」訊號的情境，本質是反指標邏輯。

Neutral

PCR 落在 90%–110% 之間，情緒無極端，市場處於正常討論區間。

Bearish

PCR 快速由高檔滑落至 < 70%（過度樂觀），或大額交易人部位異常集中單一方向——兩者都視為「情緒過熱、拉回風險上升」。

是否需等待
是——本層的訊號本質上是「不要在情緒極端時追價」，如果情緒已達極端但尚未出現反轉跡象（例如 PCR 剛突破 120% 還在上升中），建議等待情緒指標本身出現拐點再行動，不要預判反轉時機。
對下一層影響
本層與 L6 技術分析共同輸入 Technical／Flow Agent；當技術面顯示強勢但情緒面已達極端時，這是本 OS 最典型會產生「今天空手，等回檔」結論的情境。
L6

技術分析

Technical Analysis
目的
在前五層都完成「這個環境值不值得交易」的過濾後，本層負責回答最後一個問題：如果要交易，現在的價格結構是否給出足夠清楚的進場時機與停損位置。
為什麼重要
前五層決定「要不要交易」，本層決定「怎麼交易」——趨勢方向、進場時機、停損距離，全部來自本層的量價與技術指標讀數。
需要資料
台指期日 K 線（OHLCV）、成交量、20／60／200 日均線、VWAP、MACD、RSI(14)、ADX(14) 與 ±DI、ATR(14)、布林通道。
資料來源
台指期日線——本專案 tw_futures_daily 已建置，但目前每日只能累積「今天」一筆，需要至少 60–90 天歷史才能穩定計算 60MA／200MA／ADX，屬於時間累積問題，非技術問題；短期可用 TAIEX 現貨日線（已有 20 年歷史）先行計算技術指標，待期貨自身歷史夠長後再切換或並陳。
如何判讀
詳細的逐指標判讀門檻列在第 4 節評分引擎；本層的特殊之處是 ATR 與布林通道帶寬不直接產生方向分數，而是用來判斷「現在適不適合用趨勢策略」——ADX < 20 或布林帶寬過窄，代表盤整格局，此時技術面的方向性訊號應該被降權，改用區間思維。

Bullish

價格站上 20／60／200MA 呈多頭排列，MACD 金叉且柱狀擴大，ADX > 25 且 +DI > −DI，量能溫和放大。

Neutral

均線糾結、ADX < 20（無明顯趨勢）、RSI 落在 40–60、布林帶寬收窄——盤整格局，不適合趨勢策略。

Bearish

價格跌破 20／60／200MA 呈空頭排列，MACD 死叉且柱狀擴大，ADX > 25 且 −DI > +DI，下跌伴隨量增。

是否需等待
ADX < 20 時，無論均線或 MACD 顯示什麼方向，都建議標記「趨勢強度不足」，等待 ADX 回升穿越 20–25 再視為有效趨勢訊號——這是新手最常忽略、卻是最重要的一條規則。
對下一層影響
本層產生 L7 交易計畫的進場價位、方向與停損基準（以 ATR 為單位）；本層與 L3／L4／L5 的交叉一致性，直接決定 Decision Agent 最終信心分數的高低。
L7

交易計畫

Trade Plan
目的
把前六層的分析結果轉換成一句「今天該做什麼」的具體行動——方向、進場條件、部位大小的初步建議。
為什麼重要
分析做得再完整，如果最後不能收斂成一個明確、可執行的計畫，使用者還是會陷入猶豫不決，這正是本 OS 想解決的核心問題。
需要資料
本層不直接抓取外部資料，而是消化 L1–L6 的分數與 Agent 辯論結果，加上 L8 風控引擎回傳的部位與停損停利建議。
資料來源
內部運算層，資料源即前六層的輸出（見 decision_snapshots 資料表，第 11 節）。
如何判讀
本層直接採用 Decision Agent 的最終判斷，不重新評分；主要工作是把「多／空／中立 ＋ 信心分數」轉換成使用者看得懂的「策略類型」（波段做多／波段放空／區間操作／空手）。

Bullish → 波段做多

Decision Agent 判定多方且信心分數 ≥ 65，且所有 Gate 通過。

Neutral → 觀望／區間

信心分數落在 35–65 之間，或多空 Agent 意見分歧顯著（見第 6 節辯論引擎的分歧度計算）。

Bearish → 波段放空

Decision Agent 判定空方且信心分數 ≥ 65，且所有 Gate 通過。

是否需等待
任何 Gate 未通過，本層一律輸出「空手」，不論信心分數多高——這是 Gate 引擎否決權在最終輸出層的具體體現。
對下一層影響
本層的方向與信心分數是 L8 風控引擎計算實際部位大小（0–100%）與停損停利價位的直接輸入。
L8

風險管理

Risk Management
目的
不論前七層的結論多麼樂觀，本層都要用獨立、機械化的規則再檢查一次「這筆交易的風險是否可控」，並且擁有對其餘所有層級的最終否決權。
為什麼重要
波段交易者最終會虧損出局，通常不是因為判斷方向錯誤，而是因為部位太大、停損太寬、或沒有停損紀律。本層存在的意義就是把紀律變成系統的一部分，而不是依賴使用者的意志力。
需要資料
帳戶總資金、當日已實現／未實現損益、連續虧損次數、目前總曝險部位、ATR(14)（用於停損距離計算）。
資料來源
帳戶相關資料由使用者於 Onboarding 時輸入並持續維護於本地資料庫（user_risk_profile），不依賴外部 API；ATR 沿用 L6 技術分析的計算結果。
如何判讀
本層的判讀邏輯全部是機械化規則（見第 8 節風控引擎與第 7 節 Gate #26–#35），不是「多空判斷」，而是「這筆交易能不能做」的二元檢查。

通過

停損距離 ≤ 2 倍 ATR，風報比 ≥ 1.5，未達每日／每月最大虧損限制，總曝險未超過上限。

降級

部分條件邊緣（例如風報比落在 1.2–1.5），建議降低建議倉位而非直接否決。

否決

停損超過 2 倍 ATR、風報比 < 1.2、已達當日或當月最大虧損限制、連續 3 筆虧損尚未休息滿一天——任一項成立即否決本次交易，不論方向判斷多正確。

是否需等待
本層否決時一律建議等待，且會明確告知使用者「否決原因」與「需要滿足什麼條件才能解除」（例如「已達當日虧損上限，明日開盤前自動解除」）。
對下一層影響
本層是整套系統的最後一道防線，其結論會覆寫（override）L7 交易計畫的輸出——即使 Decision Agent 信心分數是 95，只要本層否決，最終輸出依然是「空手」。

06

Agent 辯論引擎

生產環境不用固定權重公式直接輸出結論——四個角色分明的 Agent 各自消化自己負責的層級，獨立給出立場、信心分數與理由，再由 Decision Agent 綜合仲裁。這個設計的目的是讓最終建議附帶反方意見，而不是一個看起來客觀、實際上把複雜情境壓成單一數字的黑盒分數。

Macro Agent · 總體經濟

輸入：L1 全球市場 ＋ L2 總體風險。分析美元、利率、VIX、美股、經濟事件對台股期貨的傳導效果。傾向於在國際盤矛盾或事件風險升高時，主動降低自己的信心分數並在理由中明確說明「為什麼不確定」。

Flow Agent · 資金流

輸入：L4 法人籌碼 ＋ L5 市場情緒。分析外資期貨、三大法人、融資融券、選擇權未平倉量比。是四個 Agent 中最常與 Technical Agent 唱反調的一個——技術面轉強但籌碼未跟上時，會明確標記「量價與籌碼背離」。

Technical Agent · 技術面

輸入：L3 台股環境 ＋ L6 技術分析。分析趨勢、均線、量價、ATR、ADX、支撐壓力。負責提出具體的進場價位與停損參考，是唯一會輸出「價位」而非只有「方向」的 Agent。

Risk Agent · 風控

輸入：Gate 引擎全部 35 項 ＋ L8 風控引擎。檢查是否有重大事件、是否符合風險報酬比、是否超過風險限制。對其餘三個 Agent 擁有否決權——只要 Risk Agent 判定「不可交易」，Decision Agent 的最終輸出必須是空手，不能被其他三個 Agent 的樂觀意見覆蓋。

Agent 輸出格式（統一介面）

interface AgentVerdict {
  agent: "macro" | "flow" | "technical" | "risk"
  stance: "bull" | "bear" | "neutral"
  confidence: number          // 0–100
  keyDrivers: string[]         // 支撐這個立場的前 2–3 個關鍵證據
  counterpoints: string[]       // Agent 自己承認的、對立場不利的證據（強制要求，不能空）
  reasoning: string            // 一段基金經理人語氣的完整推理
  vetoes: boolean              // 僅 Risk Agent 使用，true 時 Decision Agent 必須輸出空手
}

Decision Agent 仲裁邏輯

  1. 先檢查是否有任一 Agent（實務上只會是 Risk Agent）設定 vetoes: true——若有，直接輸出「建議空手」，並把否決理由放在最顯眼位置，不需要再看其他三個 Agent 的意見。
  2. 若無否決，計算四個 Agent 的立場分歧度：若 4 個 Agent 中有 ≥2 個立場相反（一個 bull 一個 bear），視為高分歧，最終建議自動降級（例如把「建議做多」降為「建議偏多、輕倉」），並在輸出中列出分歧的雙方理由讓使用者自行判斷。
  3. 若無高分歧，用信心分數加權多數決：Macro×1.0 + Flow×1.5 + Technical×1.5 + Risk×1.0（Risk 通常是二元的通過／否決，這裡的權重只在「未否決但信心偏低」時產生緩衝作用）。
  4. 輸出最終建議：方向、信心分數、支持理由列表（彙整各 Agent 的 keyDrivers）、反對理由列表（彙整各 Agent 的 counterpoints，即使最終結論是做多，也必須顯示做空方的論點）。

這一步的 UI 呈現方式建議做成「辯論紀錄」：像看一場投資會議的四人會議紀錄，而不是一個只給結論的黑盒子。使用者展開任一層都能看到「哪個 Agent 說了什麼」，這是本 OS 建立使用者信任感最重要的介面設計決策。

08

風控引擎 Risk Engine

Gate 引擎回答「能不能交易」，風控引擎回答「交易多大、停在哪裡」——兩者都獨立於 Agent 辯論引擎之外運作，屬於機械化計算層。

核心公式

// 單筆最大風險：每一筆交易願意承擔的最大虧損金額
maxRiskPerTrade = accountEquity × riskPerTradePct   // 預設 ⚠️1%，需回測校準

// ATR 停損：以市場波動度而非主觀價位決定停損距離
stopDistance = atr14 × atrMultiplier                // 預設 ⚠️1.5倍
stopPrice    = entryPrice − stopDistance             // 做多；做空則相反

// 部位大小：用最大風險金額反推口數
positionSize = floor(maxRiskPerTrade / (stopDistance × pointValue))

// 風報比：停利距離必須是停損距離的 X 倍以上才允許交易（見 Gate #27）
rewardRiskRatio = (takeProfitPrice − entryPrice) / (entryPrice − stopPrice)

// R 值：每筆交易的損益用「風險單位」而非台幣衡量，方便橫向比較策略優劣
rMultiple = actualPnL / (stopDistance × pointValue)

// 期望值：長期是否值得執行這套策略的核心指標
expectedValue = (winRate × avgWinR) − ((1 − winRate) × avgLossR)

// Kelly 建議倉位（僅供參考，實際建議用 1/4 Kelly 避免波動過大）
kellyFraction = winRate − ((1 − winRate) / (avgWinR / avgLossR))
suggestedFraction = max(0, kellyFraction × 0.25)     // ⚠️ Fractional Kelly，保守係數需回測

UI / UX 規格

視覺語言取三個產品的優點：Apple 的留白與層次、Bloomberg Terminal 的資料密度與數字對齊、TradingView 的圖表可信度；介面不是交易軟體，是每天早上讀的一份簡報。

  • 只呈現第 9 節的 9 項標準輸出，使用 Card UI，30 秒內讀完。
  • 最上方是「今日市場評分」星等 ＋ 建議策略，用最大字級呈現，其餘 7 項次之。
  • 任何一個 Gate 被觸發時，Dashboard 頂部顯示明顯的警示條（非跳出視窗），列出觸發的 Gate 名稱。

八層卡片（可展開）

  • 每張卡片預設收合，顯示：層級名稱、目前狀態（Bull／Neutral／Bear pill）、分數、一句話結論。

Agent 辯論紀錄

  • 獨立分頁或可展開區塊，以「會議紀錄」形式呈現四個 Agent 的發言，每個 Agent 一張卡片，含立場 pill、信心分數條、關鍵理由、反方論點。
  • Decision Agent 的仲裁摘要固定置頂，並附上分歧度視覺化（例如四個 Agent 立場的簡單分佈條）。

Database Schema

沿用本專案既有 Prisma 慣例（snake_case 資料表、camelCase 欄位、Decimal 用於價格）。tw_futures_daily 與 tw_options_put_call_ratio 已在既有系統上線，其餘為本 PRD 新增。

/// 每日決策快照——八層分數＋四個Agent結果＋最終建議，一天一筆，Dashboard直接讀這張表
model DecisionSnapshot {
  id              BigInt   @id @default(autoincrement())
  tradeDate       DateTime @unique @map("trade_date") @db.Date

  // 八層分數（L2/L8 無分數，只有旗標，故 nullable）
  l1GlobalScore     Decimal? @db.Decimal(4, 2)
  l3TwMarketScore   Decimal? @db.Decimal(4, 2)
  l4FlowScore       Decimal? @db.Decimal(4, 2)
  l5SentimentScore  Decimal? @db.Decimal(4, 2)
  l6TechnicalScore  Decimal? @db.Decimal(4, 2)
  totalScore        Decimal? @db.Decimal(5, 2)   // 加權總分，Decision Engine 基準版用

  // Agent 辯論結果（JSON，見 AgentVerdict 介面）
  macroVerdict      Json
  flowVerdict       Json
  technicalVerdict  Json
  riskVerdict       Json
  finalStance       FinalStance
  finalConfidence   Int      // 0-100

  // 最終輸出（對應第9節9項）
  strategy          TradeStrategy
  riskLevel         RiskLevel
  suggestedSizePct  Int
  entryCondition    String
  stopLossPrice     Decimal? @db.Decimal(10, 2)
  takeProfitPrice   Decimal? @db.Decimal(10, 2)
  supportingReasons Json     // string[]
  opposingReasons   Json     // string[]

  createdAt DateTime @default(now()) @map("created_at")

  @@map("decision_snapshots")
}

enum FinalStance { bull bear neutral }
enum TradeStrategy { swingLong swingShort rangeBound flat }
enum RiskLevel { low medium high }

/// Gate 引擎每日檢查結果，一天可能多筆（每個觸發的Gate一筆），供Dashboard警示條與歷史稽核用
model GateTrigger {
  id         BigInt   @id @default(autoincrement())
  tradeDate  DateTime @map("trade_date") @db.Date
  gateNumber Int      @map("gate_number")   // 對應第7節 #1-#35
  gateName   String   @map("gate_name")
  action     String                                // 例如 "禁止新倉"
  detail     String?                                // 觸發當下的具體數值
  createdAt  DateTime @default(now()) @map("created_at")

  @@index([tradeDate])
  @@map("gate_triggers")
}

/// 使用者風控設定，Onboarding時建立，L8風控引擎讀取
model UserRiskProfile {
  id                  Int      @id @default(autoincrement())
  accountEquity       Decimal  @map("account_equity") @db.Decimal(14, 0)
  riskPerTradePct     Decimal  @default(1.0) @map("risk_per_trade_pct") @db.Decimal(4, 2)
  dailyMaxLossPct     Decimal  @default(3.0) @map("daily_max_loss_pct") @db.Decimal(4, 2)
  monthlyMaxLossPct   Decimal  @default(10.0) @map("monthly_max_loss_pct") @db.Decimal(4, 2)
  maxExposurePct      Decimal  @default(50.0) @map("max_exposure_pct") @db.Decimal(4, 2)
  atrStopMultiplier   Decimal  @default(1.5) @map("atr_stop_multiplier") @db.Decimal(3, 2)
  consecutiveLossHalt Int      @default(3) @map("consecutive_loss_halt")
  updatedAt           DateTime @updatedAt @map("updated_at")

  @@map("user_risk_profile")
}

/// 事件行事曆（L2 資料源，v1先用人工維護）
model MacroEvent {
  id         Int      @id @default(autoincrement())

  eventType  String   @map("event_type")  // "FOMC" | "CPI" | "NFP" | "TSMC_CALL" | ...
  label      String
  gateAction String   @map("gate_action")

  @@index([eventDate])
  @@map("macro_events")
}

開發路線圖

MVP（第一階段）

  • L3（台股環境）、L4（法人籌碼，先用已上線的 PCR）、L6（技術分析，先用 TAIEX 現貨計算指標）三層先上線——這三層資料源已驗證可用，可立刻動工。
  • Gate 引擎先實作 B/C/D/E 四類（波動度、流動性、價格結構、風險管理），共 24 項，不依賴外部行事曆資料源。
  • Decision Engine 先用第 5 節的確定性公式版本上線，Agent 辯論引擎作為第二階段。
  • 風控引擎與 UserRiskProfile 從第一天就必須存在——這是本 OS 的核心承諾，不能延後。

第二階段

  • 接入三大法人台指期未平倉每日排程（L4 完整化）。
  • 調研並接入 NASDAQ／SOX 資料源、融資融券資料源、事件行事曆資料源（L1／L2 完整化）。
  • 上線 Agent 辯論引擎，取代 Decision Engine 基準版成為生產環境預設。

第三階段

  • 用累積的 DecisionSnapshot 歷史資料回測，校準所有標註 ⚠️ 的權重與門檻參數。
  • 新聞／社群情緒資料源、大額交易人集中度視覺化。
